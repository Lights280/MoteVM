# 05 · Toolchain Reference

[简体中文](../05-toolchain.md) | [English](05-toolchain.md)

This document describes the command-line tools implemented by MoteVM 0.1.0: `moteasm`, `motedis`,
`motevm`, `motear`, and the standalone build driver `builder`. Options and exit codes follow the
current `--help` output and source code; 0.x options may change.

## 1. Tool Map and Dataflow

| Tool | Role | Input | Output |
|---|---|---|---|
| `moteasm` | Assembler | `.mta` text | `.mbc` bytecode, listing |
| `motedis` | Canonical disassembler | `.mbc` | canonical `.mta` text |
| `motevm` | Load, verify and run the entry module | `.mbc` (entry + optional external modules) | script stdout, diagnostics, trace, stats |
| `motear` | MTR 1.0 pack/inspect/verify/unpack | `.mbc`, resource files, `.mtr` | `.mtr` archive or reports |
| `builder` | Project build driver | sources under `src/` | `build/<toolchain>-<arch>-<config>/bin/` |

```text
hello.mta --moteasm--> hello.mbc --motevm--> stdout / exit code
                           |
                           +--motedis--> hello.canon.mta --moteasm--> hello.mbc   (RT-1)

hello.mbc + resources --motear pack--> app.mtr
app.mtr --motear list | info | verify | unpack--> reports / unpacked directory
```

`builder` is not part of the runtime dataflow; it discovers `src/<module>` directly and invokes the
C++ compiler without reading `CMakeLists.txt` (see [06 · Build and Release](06-build.md)).

## 2. Common Conventions

### 2.1 Options

- Long options accept both `--name value` and `--name=value`; short options (`-o`, `-w`, `-C`, `-j`)
  take the next token.
- `--` ends option parsing; every following token is positional.
- `--help` and `--version` write to **stdout** and exit 0; no further arguments are processed.
- `moteasm` and `motedis` accept options before or after positional arguments; `motear` requires
  the subcommand first, with options after it; `motevm` extern options must appear before the entry
  module (see §8.4).
- A bare `-` means stdin or stdout only in `moteasm`/`motedis`; it is not an option.

### 2.2 Diagnostics

All diagnostics go to **stderr**; normal data goes to stdout. ANSI colors are never used, so
redirected output is deterministic.

| Tool | Diagnostic format |
|---|---|
| `moteasm` | `moteasm: [path:line:col: ]<error|warning>: <code>: <message>`, followed by `moteasm: N error(s), M warning(s)` |
| `motedis` | `motedis: <path>: error: <message>`; warnings use `motedis: warning: <message>` |
| `motevm` | `error: <message>` / `note: <message>` (no tool prefix) |
| `motear` | `motear: <file>: <message>` or `motear: <specific error>` |
| `builder` | `error: <message>`; usage errors are printed to stderr |

Examples:

```text
$ moteasm bad.mta
moteasm: bad.mta:3:5: error: E003: unknown mnemonic 'foo'
moteasm: 1 error(s), 0 warning(s)

$ motedis bad.mbc
motedis: bad.mbc: error: invalid header, section table or checksum
```

### 2.3 stdout, stderr and Determinism

- Normal program results and tool data go to stdout; diagnostics, notes, trace (unless redirected),
  and statistics go to stderr.
- Output contains no timestamps, host addresses, or random values; the same input produces
  byte-identical output.
- Tool artifacts (`.mbc`, disassembly text, `.mtr`, unpacked entries) are built fully in memory,
  then written through a temporary file and atomic replace; a failure never leaves a partial
  artifact. `motevm --trace-file` truncates its target directly, without atomic replace.
- `motedis --annotate` is non-canonical debug output; canonical text contains no PC comments.

### 2.4 Exit-Code Philosophy

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | Usage error (option, argument, mutually exclusive combination, input=output) |
| `2` | Input/verification error (unreadable file, invalid format, assembly diagnostics, unlinked import) |
| `3` | Runtime trap (only `motevm`; `motear` uses it for I/O errors) |
| `4` | Internal/environment error (self-check failure, write failure, invariant error) |

`builder` uses a different scheme: `0` success, `1` build failure, `2` usage, `3`
environment/toolchain. Per-tool details are in §8.5.

## 3. moteasm

`moteasm` assembles self-ISA `.mta` text into MOTEBC 1.0 `.mbc`. Language, instructions, and
diagnostic codes are documented in [self/moteasm.md](self/moteasm.md),
[01 · ISA Reference](01-isa.md), and [02 · MOTEBC Format](02-bytecode-format.md).

- The default output replaces the input extension with `.mbc`; `-o -` writes stdout.
- A DEBUG section is generated by default when the source contains `.loc`/`.local`; `-g` forces it,
  `--no-debug` omits it.
- stdout is empty on success. On failure, no output file is created or modified.
- `--listing FILE` writes a text listing; `--max-errors N` limits retained diagnostics (default 20,
  0 = unlimited request but at most 1000 records are stored, range 0..100000).
- `--warn-as-error` turns warnings into failures.
- `--check-roundtrip` disassembles and re-assembles in memory and compares bytes (see §9).

## 4. motedis

`motedis` renders a valid `.mbc` as canonical text that `moteasm` can re-assemble.

- Input goes through the same load and verification as `motevm`; an invalid module produces no output.
- The default output is stdout; `-o FILE` writes atomically, `-o -` writes stdout.
- `--no-debug` omits `.loc`/`.local`, so byte-level round-trip is not guaranteed.
- `--annotate` appends `; pc=<absolute byte offset>` to each instruction; debug use only.
- `--check-roundtrip` re-assembles in memory and compares bytes (see §9).
- Detailed rules are in [self/motedis.md](self/motedis.md).

## 5. motevm

The current `motevm` uses positional arguments and has no subcommands:

```text
motevm [extern_parameters] <entry_mbc_module> [ext_mbc_modules] [intern_parameters]
```

- Only the entry module runs. Consecutive `.mbc` tokens after it (case-insensitive suffix) are
  loaded as external modules; they contribute constants only and are not executed.
- Remaining tokens are intern parameters reserved for scripts; they are parsed and currently
  ignored.
- `-s/--status` writes deterministic statistics to stderr after the run; `-d/--debug` prints module
  and stop summaries.
- `-i`/`--step`/`--break`/`--trace` install the debug hook; the REPL reads commands from stdin and
  writes prompts and results to stderr.
- `-w/--workspace DIR` is the only directory grant; without it scripts have stdio only.
- See [self/cli.md](self/cli.md) for the full reference.

## 6. motear

`motear` reads and writes MTR 1.0 archives (`.mtr`). Container layout, validation, and CRC rules are
in [07 · MTR Format](07-mtr-format.md).

### 6.1 Subcommands

```text
motear pack -o OUT.mtr [options] --module FILE[=NAME]... [--resource FILE[=NAME]]...
motear list FILE.mtr [--verbose] [--verify]
motear info FILE.mtr [--json]
motear verify FILE.mtr [--strict] [--no-modules]
motear unpack FILE.mtr -C DIR [--force] [--module NAME]... [--resource NAME]...
```

The subcommand must be the first argument after the program name (options cannot precede it); a
missing or unknown subcommand exits 1.

### 6.2 `pack`

| Option | Description |
|---|---|
| `-o, --output FILE` | Output archive, **required** |
| `--module FILE[=NAME]` | Add a MoteBC module, repeatable; `NAME` defaults to the file basename |
| `--resource FILE[=NAME]` | Add a resource, repeatable; `NAME` defaults to the file basename |
| `--entry NAME` | Entry module name; required with multiple modules |
| `--name NAME` | Package name; defaults to the output file stem |
| `--package-version V` | Package version; defaults to `0.0.0` |
| `--description TEXT` | Description |
| `--author TEXT` | Author |
| `--license TEXT` | License |
| `--build-id TEXT` | Build identifier / provenance |

Rules:

- The output path must differ from every `--module`/`--resource` input.
- With a single module and no `--entry`, the writer stores that module name in manifest key 3;
  multiple modules without `--entry` exit 2.
- `--entry` must name a module entry; `--entry` without any `--module` exits 2.
- `created-by` is written automatically as `motear 0.1.0`.
- Each input is limited to 64 MiB; the archive is limited to 256 MiB. Exceeding either exits 2.
- On success stdout prints `wrote OUT.mtr (N module(s), M resource(s), S bytes)`.

### 6.3 `list`

By default it validates the container only (header, CRC, TOC, manifest, names); `--verify`
additionally verifies MoteBC modules (the help text calls this "entry CRCs and modules").
`--verbose` shows each entry's offset and the full manifest.

```text
mtr 1.0 entries=2 modules=1 resources=1 size=1112
module        432  c8a557f5  hello.mbc
resource      371  6eb5bb10  src/hello.mta
```

`--verbose` appends `offset=...` to each entry and prints:

```text
  package (1): demo
  version (2): 1.2.3
  entry (3): hello.mbc
  description (4): demo package
  author (5): tester
  license (6): MIT
  build-id (7): b42
  created-by (8): motear 0.1.0
```

### 6.4 `info`

Prints a key-value summary of the header and manifest; `--json` prints JSON with a fixed key order:

```json
{
  "file": "app.mtr",
  "format": "MTR 1.0",
  "size": 1112,
  "entries": 2,
  "modules": 1,
  "resources": 1,
  "package_name": "demo",
  "package_version": "1.2.3",
  "entry_module": "hello.mbc",
  "description": "demo package",
  "author": "tester",
  "license": "MIT",
  "build_id": "b42",
  "created_by": "motear 0.1.0"
}
```

`info` does not run MoteBC verification, but the container itself is still fully validated.

### 6.5 `verify`

- Default: full container validation plus MoteBC verification of every module.
- `--no-modules`: container-only check; skip MoteBC verification.
- `--strict`: on top of the selected verification mode, additionally require a manifest package
  name, a package version, and a uniquely resolvable entry module (combinable with `--no-modules`).
- Success output: `ok: FILE (N entries, M modules, K resources)`.

### 6.6 `unpack`

| Option | Description |
|---|---|
| `-C, --directory DIR` | Destination directory, **required**; created when missing |
| `--force` | Replace an existing **regular file** |
| `--module NAME` | Extract only the named module, repeatable |
| `--resource NAME` | Extract only the named resource, repeatable |

- Without filters, every entry is extracted; filters match the full in-archive name exactly.
- Symbolic links, non-regular targets, paths outside the destination directory, and an existing
  `<target>.tmp` are rejected.
- Success output: `extracted N entry(ies) to <absolute path>`.

### 6.7 Manifest Fields

The manifest is a TLV list sorted by ascending key. Known keys:

| Key | Name | Source |
|---|---|---|
| 1 | `package` | `--name` (default: output stem) |
| 2 | `version` | `--package-version` (default `0.0.0`) |
| 3 | `entry` | `--entry` or the only module name |
| 4 | `description` | `--description` |
| 5 | `author` | `--author` |
| 6 | `license` | `--license` |
| 7 | `build-id` | `--build-id` |
| 8 | `created-by` | Automatic: `motear 0.1.0` |

### 6.8 Exit Codes

| Code | Scenario |
|---|---|
| `0` | Success |
| `1` | Usage error |
| `2` | Archive/module verification failure, data limit exceeded, target exists without `--force`, unsafe unpack path |
| `3` | I/O error (read/create/write failure) |
| `4` | Internal error (reserved by the current implementation; normal paths do not produce it) |

### 6.9 Option Summary

| Option | Subcommand | Description |
|---|---|---|
| `-o, --output FILE` | `pack` | Output archive (required) |
| `--module FILE[=NAME]` | `pack` / `unpack` | pack: add a module; unpack: filter by `NAME` |
| `--resource FILE[=NAME]` | `pack` / `unpack` | pack: add a resource; unpack: filter by `NAME` |
| `--entry NAME` | `pack` | Entry module |
| `--name NAME` | `pack` | Package name |
| `--package-version V` | `pack` | Package version |
| `--description TEXT` | `pack` | Description |
| `--author TEXT` | `pack` | Author |
| `--license TEXT` | `pack` | License |
| `--build-id TEXT` | `pack` | Build identifier |
| `-C, --directory DIR` | `unpack` | Destination directory (required) |
| `--force` | `unpack` | Replace an existing regular file |
| `--verbose` | `list` | Show offsets and manifest |
| `--verify` | `list` | Also verify modules |
| `--json` | `info` | JSON output |
| `--strict` | `verify` | Require package name, version, and a resolvable entry |
| `--no-modules` | `verify` | Skip MoteBC verification |
| `-h, --help`, `-v, --version` | All | Help/version |
| `--` | All | End option parsing |

## 7. builder

`builder` is a single-translation-unit build driver that does not read `CMakeLists.txt`:

```text
builder [build] [options] [target...]
builder clean | rebuild | self | doctor | targets | help
```

| Command | Behavior |
|---|---|
| `build` (default) | Compile and link the selected targets |
| `clean` | Remove builder outputs and state; never touches CMake files |
| `rebuild` | `clean` followed by `build` |
| `self` | Rebuild `builder` itself with the current builder |
| `doctor` | Print toolchain and build configuration |
| `targets` | List targets, sources, and link relationships |
| `help` | Usage |

| Option | Description |
|---|---|
| `-j, --jobs N` | Parallel compile jobs (default: hardware concurrency) |
| `--compiler X` | `clang` / `gcc` / `msvc` (clang++ preferred by default) |
| `--arch X` | `x86` / `x64` (default: host architecture) |
| `--release` / `--debug` | Configuration; Release by default |
| `--cxx PATH` | Explicit C++ compiler; family detected from the file name |
| `--build-dir DIR` | Output root; default `<root>/build` |
| `--root DIR` | Project root; default auto-detect `src/motevm` + `src/builder` |
| `--werror` | Treat warnings as errors |
| `--sanitize` | ASan + UBSan (MSVC: ASan only) |
| `--force` | Ignore the cache and rebuild everything |
| `-n, --dry-run` | Print commands without running them |
| `-v, --verbose` | Print cache hits and full command lines |
| `--version` | Version |
| `-h, --help` | Help |

Exit codes: `0` success, `1` build failure, `2` usage, `3` environment/toolchain. See
[06 · Build and Release](06-build.md) for build details.

## 8. CLI Design

### 8.1 Common Conventions

- The tool name is the executable name; Windows adds `.exe`.
- `--help`/`--version` write stdout and exit 0.
- Diagnostics go to stderr; data goes to stdout. There is no color control.
- Paths are echoed exactly as given on the command line, without absolutization (the `motevm -d`
  workspace note is the exception: it prints the canonical root).
- Numeric arguments are decimal; the meaning of `0` is defined per option. `motevm --trace-limit`
  also accepts a `0x` prefix.
- The shared mechanical layer lives in `src/include/common/` (namespace `TOOL`) and only handles
  option matching/values, version lines, and usage headers; each tool keeps its own options, help
  text, and positional rules.

### 8.2 `moteasm`

```text
moteasm [options] <input.mta>
```

| Option | Description |
|---|---|
| `-o, --output FILE` | Output `.mbc`; default replaces the input extension with `.mbc`; `-` = stdout |
| `-g, --debug` | Force a DEBUG section |
| `--no-debug` | Omit the DEBUG section; combined with `-g` exits 1 |
| `--listing FILE` | Write a text listing |
| `--max-errors N` | Retain at most N errors (default 20, range 0..100000; 0 = unlimited request, internal cap 1000) |
| `--warn-as-error` | Treat warnings as failures |
| `--check-roundtrip` | Assemble, disassemble, re-assemble, compare bytes (RT-1) |
| `--version`, `--help` | Version/help; stdout, exit 0 |

- If `input` is `-`, `-o` must be given explicitly.
- `input` and `-o` (both non-stdio tokens) naming the same path exits 1.
- stdout is empty on success.

### 8.3 `motedis`

```text
motedis [options] <input.mbc>
```

| Option | Description |
|---|---|
| `-o, --output FILE` | Canonical text output; default stdout; `-` = stdout |
| `--no-debug` | Omit `.loc`/`.local` |
| `--annotate` | Append `; pc=<8 hex digits>` to each instruction (non-canonical) |
| `--check-roundtrip` | Re-assemble in memory and compare bytes (RT-1) |
| `--version`, `--help` | Version/help; stdout, exit 0 |

- `--annotate` and `--check-roundtrip` are mutually exclusive and exit 1.
- An input of `-` reads stdin.
- Input and output naming the same path (both non-stdio tokens) exits 1.
- An invalid module exits 2 and writes no output.

### 8.4 `motevm`

```text
motevm [extern_parameters] <entry_mbc_module> [ext_mbc_modules] [intern_parameters]
```

| Option | Description |
|---|---|
| `-v, --version` | Print version, exit 0 |
| `-h, --help` | Print usage to stdout, exit 0 |
| `-d, --debug` | Print `note:` summaries and stop context |
| `-r, --release` | Errors only (default); when both `-d` and `-r` are given, the later one wins |
| `-s, --status` | Write statistics to stderr after the run (see [self/cli.md](self/cli.md) §6) |
| `-i, --interactive` | Stop before the first entry instruction and enter the REPL |
| `--step` | Stop before the first instruction (implies `--interactive`) |
| `--break SPEC` | Set a breakpoint, repeatable; syntax in [self/cli.md](self/cli.md) §11.1 |
| `--trace LVL` | `off` (default) / `call` / `exec` / `full` |
| `--trace-file PATH` | Trace target; default stderr, `-` = stdout |
| `--trace-limit N` | Record at most N lines; 0 = unlimited |
| `-w, --workspace DIR` | The only directory grant; default stdio only; a later value overrides an earlier one |

Positional rules:

- Extern options must precede the entry module; a missing entry module or unknown option exits 1.
- The entry module is the first non-option token; consecutive `.mbc` tokens after it (suffix
  case-insensitive) are external modules.
- All remaining tokens are intern parameters, saved verbatim and currently ignored; tokens starting
  with `-` after the entry are not treated as options.
- `--` ends the extern segment; the next token becomes the entry module even if it starts with `-`.
- Missing/empty values for `--break` or `--trace-file`, invalid `--trace` or `--trace-limit` values,
  and an empty `--workspace=` exit 1.
- `-w DIR` takes the next token verbatim; a missing value or an empty `--workspace=` exits 1.

### 8.5 Output and Exit Codes

| Tool | stdout | stderr |
|---|---|---|
| `moteasm` | Empty on success; `.mbc` bytes with `-o -` | Diagnostics, I/O errors |
| `motedis` | Canonical text; or `-o -` | Warnings, errors |
| `motevm` | Script output (`print`/`print_str`); trace with `--trace-file -`; help/version | `note:`/`error:`, REPL, default trace, `--status` |
| `motear` | pack/list/info/verify/unpack reports | Errors |
| `builder` | Build progress/reports, `targets`/`doctor`/help | Errors and usage |

| Tool | `0` | `1` | `2` | `3` | `4` |
|---|---|---|---|---|---|
| `moteasm` | Success | Usage | Source/input error | — | Internal, I/O, round-trip self-check failure |
| `motedis` | Success | Usage | Read/parse/verify failure | — | Write, round-trip, or internal error |
| `motevm` | Success (including debugger `quit`) | Usage | Load/verify/workspace/breakpoint/trace-file error | Runtime trap | Internal error (registration failure, memory init failure, etc.) |
| `motear` | Success | Usage | Archive/verify/data error | I/O error | Internal error (declared, reserved) |
| `builder` | Success | Build failure | Usage | Environment/toolchain | — |

A `motevm` trap diagnostic looks like:

```text
error: trap 3 (TRAP) at pc=8
```

`pc` here is the execution `lastPc`; the `-d` stop context uses the faulting instruction address
`errorPc` (see [self/cli.md](self/cli.md) §7).

### 8.6 Built-in Host Functions

The CLI registers these host functions before loading modules. Names match byte-exactly and the
arity must match the `.import` declaration.

Always registered:

| Name | Arity | Behavior |
|---|---|---|
| `print` | 1 | Write the argument as signed 32-bit decimal + `\n` to stdout |
| `print_str` | 2 | Write the raw bytes at `(addr, len)` + `\n` to stdout |
| `eprint_str` | 2 | Same as `print_str`, but to stderr |
| `total_prints` | 0 | Return the cumulative line count of `print`/`print_str`/`eprint_str` |
| `const_addr` | 1 | Return the address of the current module's constant payload; failure `0xFFFFFFFF` |
| `const_len` | 1 | Return the length of the current module's constant payload; failure `0xFFFFFFFF` |
| `mem_alloc` | 1 | 8-byte aligned bump allocation; return address; failure `0xFFFFFFFF` |
| `mem_free` | 1 | No-op, returns `0`; invalid argument returns `-5` |

Registered only with `-w/--workspace`:

| Name | Arity | Behavior |
|---|---|---|
| `file.read` | 4 | `(pathAddr, pathLen, bufAddr, maxLen)` → bytes read (0 = EOF) |
| `file.write` | 4 | `(pathAddr, pathLen, dataAddr, dataLen)` → bytes written (truncate) |
| `file.append` | 4 | Same, append mode |
| `file.exists` | 2 | `(pathAddr, pathLen)` → `0`/`1` |
| `file.size` | 2 | `(pathAddr, pathLen)` → size; non-regular file ⇒ `-3` |
| `file.remove` | 2 | `(pathAddr, pathLen)` → `0`; regular files only |

Without `-w`, a module that imports `file.*` fails at load time (unlinked import, exit 2). Full
argument semantics, side effects, and error codes are in [self/cli.md](self/cli.md) §10. stdout is
line-buffered and flushed after every `print*`.

### 8.7 stdio ABI and Negative Error Codes

The current ABI is **transitional**: registers are raw 32-bit values with no `Value`/`String`, and
byte strings are passed as `(address, length)` pairs into the 4 GiB linear memory. Addresses come
from `const_addr` (constant pool) or `mem_alloc` (heap). Return values are interpreted as `dword`:
non-negative means success, negative (two's complement) is an error code.

| Value | Meaning |
|---|---|
| `0` | Success |
| `-3` | System I/O error (open/read/write/remove failure, missing parent directory, target is not a regular file) |
| `-4` | Denied (path outside the workspace, or no workspace) |
| `-5` | Bad argument (path length 0 or > 4096, embedded NUL, buffer out of range, single I/O > 16 MiB; arity mismatch where applicable) |

Query functions (`const_addr`, `const_len`, `mem_alloc`) return `0xFFFFFFFF` (`NO_INDEX`) on failure
instead of a negative error code.

Limits:

| Item | Value |
|---|---|
| Linear memory | 4 GiB |
| Memory block | 64 KiB |
| Single read/write | ≤ 16 MiB |
| Path bytes | 1..4096, no NUL |
| Single `mem_alloc` | 1..256 MiB; total bounded by 4 GiB |
| File open mode | Binary, no newline translation |

The current CLI has **no** `io.*` imports; the stdio capability is exactly `print`/`print_str`/
`eprint_str` above. This ABI will change with the value model; `.import` declarations and
documentation follow the current `--help` and source.

### 8.8 Workspace and Capability Model

`-w/--workspace DIR` is `motevm`'s only directory grant:

| State | Module files | Script capability |
|---|---|---|
| No `-w` (default) | Opened verbatim from the command line (relative to cwd) | stdio only; no directory is granted |
| `-w DIR` given | Relative paths resolve against `DIR`; absolute paths are taken as-is; both must canonicalize inside `DIR` | Reads and writes must stay inside `DIR` |

- The root is canonicalized and validated as an existing directory before any module loads; failure
  exits 2.
- Containment is checked component-wise (case-insensitive on Windows); `..` is allowed when
  canonicalization stays inside the root.
- Empty paths, embedded NUL, and the Windows drive-relative (`C:foo`) and root-relative (`\foo`)
  forms are `invalid path` on Windows.
- The write side requires the target parent to exist and stay inside the root. Current `motevm`
  write paths are `--trace-file` and `file.*`.
- Each module path is resolved before it is opened; an escape exits 2 and no bytecode runs.

## 9. Round-Trip Guarantees

| Level | Condition | Verification |
|---|---|---|
| RT-1 byte equality | Canonically laid out `.mbc` (`moteasm` output) | `moteasm --check-roundtrip`, `motedis --check-roundtrip` |
| Idempotence | Canonical text is a fixed point | `dis(asm(dis(bc))) == dis(bc)` |
| RT-2 executable | Any valid module re-assembles and executes | disassemble → assemble → `motevm` |
| RT-3 structure | Names/indices may be renumbered | `#n` fallback + structural assertions |

- `moteasm --check-roundtrip`: assemble → canonical disassemble → re-assemble → compare bytes;
  failure exits 4.
- `motedis --check-roundtrip`: disassemble → re-assemble in memory → compare bytes; failure exits 4
  and reports the first difference.
- `--no-debug` drops the DEBUG section, so only semantics (RT-2) are guaranteed, not byte equality.
- Non-canonical layout (FUNCS order differs from CODE order) or name fallback (non-identifier or
  duplicate string constant) produces a stderr warning; RT-1 is not guaranteed in that case.
