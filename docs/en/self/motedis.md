# motedis Disassembler

[简体中文](../../self/motedis.md) | [English](motedis.md)

`motedis` renders a valid MOTEBC 1.0 `.mbc` module as **canonical** `.mta` text. Canonical text can
be re-assembled by `moteasm`; for canonically laid-out modules the bytes are guaranteed to match.
General tool conventions are in [05 · Toolchain Reference](../05-toolchain.md).

## 1. Purpose and Dataflow

```text
foo.mbc --motedis--> foo.canon.mta --moteasm--> byte-identical foo.mbc   (RT-1)
```

- Input goes through the same load and verification as `motevm`; invalid modules produce no output.
- Canonical text declares constants explicitly: `.const` in index order, names first, `#n` fallback
  when necessary.
- `moteasm` output with canonical layout is guaranteed RT-1 byte equality; any valid module is
  guaranteed to re-assemble into an executable module (RT-2).
- Non-canonical layout or name fallback produces a stderr warning.

## 2. Canonical Structure

```text
; canonical text generated by motedis 1.0; format MOTEBC 1.0
[.module "..."]
[.meta <key>, "..."]        ; ascending key; key 1 is emitted as .module
[.const <literal>]          ; CONST index order
[.import <name> <arity>]    ; IMPORTS order
[.global <name> ...]        ; GLOBALS order
.entry <function>           ; always emitted
.func <name> <arity> <regcnt> [flags=0x01]
[.local <name>, r<slot>[, param], start=<n>, end=<n>]
L0000:
[.loc ["<file>", ]<line>[, <column>]]
    <MNEMONIC> ...
.end
```

The output order is fixed: header comment → `.module` → `.meta` (ascending key) → `.const` (index
order) → `.import` (index order) → `.global` (index order) → `.entry` → `.func` (FUNCS index order).

## 3. Formatting Rules

### 3.1 General

- Mnemonics are uppercase, directives lowercase; function bodies use 4-space indentation; one
  statement per line.
- Labels are `L%04X`: function-relative pc (uppercase hex, at least 4 digits). The first instruction
  of a function and every `JMP`/`JZ`/`JNZ` target get a label; jumps always print labels.
- Files use LF newlines; output contains no timestamps or random values.

### 3.2 Constants and Names

| Constant kind | Text |
|---|---|
| Null | `null` |
| Bool | `true` / `false` |
| Int | Signed decimal |
| Float | Shortest round-trip decimal; integral values get `.0`; `nan`/`-nan`/`inf`/`-inf` are special-cased by bits |
| Float without bit-exact round-trip | `f64=0x<16 uppercase hex digits>` |
| String | Double quotes; `\\`, `\"`, `\n`, `\r`, `\t`, printable ASCII and valid UTF-8 verbatim, otherwise `\xHH` |

Name rules:

- A valid identifier (`[A-Za-z_][A-Za-z0-9_]*`) whose string constant is the first of its value prints
  as the name.
- Anonymous FUNCS/GLOBALS print as `anonymous`.
- A name that is not a valid identifier, or a duplicate string constant value, falls back to
  `#<CONST index>`.
- `.entry`/`CALL` fall back to `#<FUNCS index>`.
- `.import` names fall back to `#<CONST index>`; `HOSTCALL` names fall back to
  `#<IMPORTS index>`. The two index spaces are different.
- Import names may be dotted identifiers such as `file.write`; canonical text
  prints them directly.
- A name fallback emits a `W004` warning on stderr.

### 3.3 Directives

| Directive | Format |
|---|---|
| `.module` | `.module "<module name>"`, only when META key 1 exists |
| `.meta` | `.meta <key>, "<escaped bytes>"`, key decimal, ascending |
| `.const` | `.const <literal>`, one line per CONST entry |
| `.import` | `.import <name> <arity>` |
| `.global` | `.global <name> [const] [<literal> \| #<const index>]` |
| `.entry` | `.entry <function>`, always emitted |
| `.func` | `.func <name> <arity> <regcnt> [flags=0x01]` |
| `.local` | `.local <name>, r<slot>[, param], start=<n>, end=<n>` |
| `.loc` | `.loc ["<file>", ]<line>[, <column>]` |

`.local` lines are sorted by `(startPc, slot)` and emitted before the function body. A label comes
before `.loc`, and `.loc` comes before the instruction at the matching pc; when META key 2 exists,
every `.loc` carries the file name, and `column` is omitted when it is 0. Directives and labels are
flush left; only instructions are indented by 4 spaces.

### 3.4 Instructions

| Instruction format | Output |
|---|---|
| No operands | `MNEMONIC` |
| One register | `MNEMONIC rA` |
| Two registers | `MNEMONIC rA, rB` |
| Register + 8-bit immediate | `MNEMONIC rA, rB, +c` |
| Three registers | `MNEMONIC rA, rB, rC` |
| 16-bit immediate | `MNEMONIC rA, 0x%04X`; `JZ`/`JNZ` print `rA, L%04X` |
| 24-bit immediate | `JMP L%04X`; `TRAP <name>` (decimal when the name is unknown) |
| 16-bit target | `CALL rA, <function>` / `HOSTCALL rA, <import>` |
| Unknown/invalid opcode | `.word 0x%08X` (should not occur in a valid module) |

`LOAD`/`STO` print `rA, rB, +c`; `LLO`/`LHI` print `0x%04X`.

### 3.5 DEBUG and `--no-debug`

- With a DEBUG section, `.loc` (at line changes) and `.local` (`param` plus numeric `start`/`end`)
  are emitted.
- `--no-debug` omits `.loc`/`.local`. Canonical text cannot express a DEBUG section, so RT-1 is
  given up and only RT-2 (re-assembled module executes) is guaranteed. `--no-debug` and
  `--check-roundtrip` are mutually exclusive (exit 1).
- `motedis --check-roundtrip` handles an "empty DEBUG section" specially: when the input header has
  the DEBUG flag set but canonical text has no `.loc`/`.local`, re-assembly forces the DEBUG section
  back before comparison.

### 3.6 `--annotate`

`--annotate` appends `; pc=0x%08X` (absolute byte offset in module CODE, 8 uppercase hex digits) to
each instruction:

```text
    LLO r0, 0x0000 ; pc=0x00000000
    HOSTCALL r1, const_addr ; pc=0x00000004
```

This output is **not** canonical text, cannot participate in round-trip, and is mutually exclusive
with `--check-roundtrip`.

## 4. Warnings

Warnings go to stderr as `motedis: warning: <message>`:

- Non-canonical layout (FUNCS order differs from CODE offset order, or an unexpected hole):

  ```text
  non-canonical function layout: FUNCS order differs from CODE order; round-trip byte equality is not guaranteed
  ```

- Name fallback:

  ```text
  W004: some names use #n fallbacks (non-identifier or duplicate string constants)
  ```

Warnings do not affect the exit code; stdout still contains canonical text.

## 5. CLI

```text
motedis [options] <input.mbc>
```

| Option | Description |
|---|---|
| `-o, --output FILE` | Canonical text output; default stdout; `-` = stdout |
| `--no-debug` | Omit `.loc`/`.local` |
| `--annotate` | Append `; pc=0x...` to each instruction (non-canonical) |
| `--check-roundtrip` | Re-assemble in memory and compare bytes (RT-1) |
| `--version`, `--help` | Version/help; stdout, exit 0 |

- An input of `-` reads stdin.
- `--annotate` or `--no-debug` together with `--check-roundtrip` are mutually
  exclusive and exit 1.
- Input and output naming the same path (both non-stdio tokens) exit 1.
- Output is built fully in memory and written once; file output uses atomic replace.
- An invalid module prints `motedis: <path>: error: <message>`, exits 2, and writes no output.

Exit codes:

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | Usage error (unknown option, missing input, mutually exclusive options, input=output) |
| `2` | Read/parse/verification failure |
| `4` | Write, round-trip self-check, or internal error |

## 6. Round-Trip Guarantees

| Level | Condition | Tool |
|---|---|---|
| RT-1 byte equality | Canonically laid-out module | `motedis --check-roundtrip`, `moteasm --check-roundtrip` |
| Idempotence | `dis(asm(dis(bc))) == dis(bc)` | Canonical text is a fixed point |
| RT-2 executable | Any valid module | disassemble → assemble → `motevm` |
| RT-3 structural equivalence | Names/indices may be renumbered | `#n` fallback + structural assertions |

`--check-roundtrip` behavior:

1. Build canonical text;
2. Re-assemble it in memory with `moteasm`;
3. Compare byte-for-byte with the input;
4. On failure, report the first difference on stderr and exit 4:

```text
motedis: error: round-trip byte comparison failed: first difference at byte 00000010 expected 0x00 got 0x04
```

## 7. Example

```text
$ moteasm hello.mta -o hello.mbc
$ motedis hello.mbc
; canonical text generated by motedis 1.0; format MOTEBC 1.0
.module "hello"
.const "hello, mote"
.const "print_str"
.const "const_addr"
.const "const_len"
.const "main"
.import print_str 2
.import const_addr 1
.import const_len 1
.entry main
.func main 0 8
L0000:
    LLO r0, 0x0000
    HOSTCALL r1, const_addr
    LLO r0, 0x0000
    HOSTCALL r2, const_len
    MOV r0, r1
    MOV r1, r2
    HOSTCALL r3, print_str
    LLO r0, 0x0000
    RET r0
.end
```

The corresponding source is [examples/hello.mta](../../examples/hello.mta). Re-assemble and run:

```text
$ moteasm hello.canon.mta -o hello.mbc
$ motevm hello.mbc
hello, mote
```
