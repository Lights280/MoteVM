# 02 · MOTEBC 1.0 字节码格式

[简体中文](02-bytecode-format.md) | [English](en/02-bytecode-format.md)

> **版本说明**：MOTEBC 格式版本为 **1.0**，本文对应 MoteVM **0.1.0** 的当前实现。仓库尚未发布带版本标签的正式发行版，因此本文属于尽力而为的参考；若本文与实现不一致，以 `src/include/parse.hpp`、`src/include/parse.cpp`、`src/include/verifier.cpp` 为准。MOTEBC 文件后缀为 `.mbc`。

## 1. 总览

MOTEBC 1.0 是一个固定头部加段表、随后是若干 8 字节对齐段的容器。所有多字节整数均为**小端**。

```text
┌──────────────────────────────────────────────────────────────┐
│ Header (32 bytes, offset 0)                                  │
│   magic, major/minor, flags, entry, section_count,           │
│   file_size, CRC-32C, reserved                               │
├──────────────────────────────────────────────────────────────┤
│ Section Table (section_count × 24 bytes, right after header) │
│   each: u32 id, u32 flags, u64 offset, u64 size              │
├──────────────────────────────────────────────────────────────┤
│ Section data (each 8-byte aligned, non-overlapping)          │
│   1 META | 2 CONST | 3 FUNCS | 4 CODE | 5 GLOBALS            │
│   6 IMPORTS | 7 DEBUG (optional)                             │
└──────────────────────────────────────────────────────────────┘
```

### 1.1 基本约定

| 项目 | 规则 |
|---|---|
| 字节序 | 文件内所有多字节整数均为小端 |
| 段对齐 | 每个段的 `offset` 与 `size` 都必须是 8 的倍数 |
| 段表顺序 | 段表项按 `id` **严格升序**排列（因此 id 唯一） |
| 段物理顺序 | 解析器只要求段区间不重叠；规范写入端按 id 升序紧邻排列 |
| 文件大小 | 不超过 `MAX_MODULE_BYTES` = 64 MiB |
| 静态表计数 | `CONST`、`FUNCS`、`GLOBALS`、`IMPORTS` 的 `count` 均不得超过 65536 |
| 字符串上限 | 单个 String 常量的 payload 不得超过 16 MiB |
| 完整覆盖 | 每个段内部由条目或填充精确覆盖；填充必须为 0 |
| 校验 | 头部 `checksum` 覆盖整个文件，计算时该字段视为 0 |
| 失败处理 | 加载即验证；任一检查失败则整个模块被拒绝，不执行任何字节码 |

### 1.2 段 ID

| id | 段名 | 必需 | 内容 |
|---:|---|---|---|
| 1 | META | 是 | 元数据 TLV（模块名、源文件、build id、注释） |
| 2 | CONST | 是 | 常量池 |
| 3 | FUNCS | 是 | 函数表 |
| 4 | CODE | 是 | 32 位指令字序列 |
| 5 | GLOBALS | 是 | 全局槽定义 |
| 6 | IMPORTS | 是 | 宿主导入定义 |
| 7 | DEBUG | 条件必需 | 调试信息；存在性与头部 `flags.bit0` 双向一致 |

段 1–6 必须各出现一次。段 7 只允许在 `flags.bit0 = 1` 时出现，且 `flags.bit0 = 1` 时必须有段 7。id 大于 7 的未知段仅允许 `flags = 0`，解析器跳过其内容。

有效模块至少需要一个函数：头部 `entry` 必须指向一个存在的 FUNCS 条目，且该函数 `arity = 0`。

## 2. 头部（32 字节）

| 偏移 | 大小 | 字段（代码名） | 类型 | 含义 | 校验 |
|---:|---:|---|---|---|---|
| 0x00 | 4 | `magic` | `u8[4]` | `4D 4F 54 45`（`"MOTE"`） | 必须精确匹配 |
| 0x04 | 2 | `majorVer` | `u16` | 主版本 | 必须等于 1 |
| 0x06 | 2 | `minorVer` | `u16` | 次版本 | 必须等于 0（当前读取器支持的 minor） |
| 0x08 | 4 | `flags` | `u32` | bit0 = `DEBUG_PRESENT`（`0x1`）；其余位保留 | 仅 bit0 可置位 |
| 0x0C | 4 | `entry` | `u32` | 入口函数的 FUNCS 索引 | 语义阶段检查：`< func_count` 且 `arity = 0` |
| 0x10 | 2 | `seccnt` | `u16` | 段表项数 | ≥ 6；段表必须完整落在文件内 |
| 0x12 | 2 | `reserved0` | `u16` | 保留 | 必须为 0 |
| 0x14 | 4 | `fileSize` | `u32` | 文件总字节数 | 必须等于实际输入长度 |
| 0x18 | 4 | `checksum` | `u32` | 整个文件的 CRC-32C | 计算时把本字段视为 0 |
| 0x1C | 4 | `reserved1` | `u32` | 保留 | 必须为 0 |

头部检查顺序（实现顺序）：

1. 输入长度 ≥ 32、≤ `MAX_MODULE_BYTES`。
2. magic、major/minor、flags 保留位、`reserved0`、`reserved1`、`fileSize == 输入长度`。
3. `seccnt ≥ 6` 且 `32 + 24 × seccnt ≤ fileSize`。
4. CRC-32C 校验。
5. 解析并校验段表。

头部中的 `entry` 不在头部检查阶段验证，而是在全部段解析完成后由跨表规则 V76/V77 检查。

## 3. 段表（每项 24 字节）

段表紧跟在 32 字节头部之后，共 `seccnt` 项。

| 项内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 4 | `id` | `u32` | 段 id |
| 0x04 | 4 | `flags` | `u32` | 段标志；当前格式要求为 0 |
| 0x08 | 8 | `offset` | `u64` | 段数据在文件中的起始偏移 |
| 0x10 | 8 | `size` | `u64` | 段数据字节数 |

段表不变量：

| 编号 | 规则 |
|---|---|
| S1 | 段表区间 `[32, 32 + 24 × seccnt)` 完全位于文件内（u64 运算） |
| S2 | `id != 0` |
| S3 | 段表项按 `id` 严格升序，因此 id 不重复 |
| S4 | 已知段（id 1–7）的 `flags` 必须为 0；未知段的 `flags` 也必须为 0，否则拒绝 |
| S5 | `offset % 8 == 0` 且 `size % 8 == 0` |
| S6 | `offset ≥ 32 + 24 × seccnt`（段数据不得与头部或段表重叠） |
| S7 | `offset + size ≤ fileSize`，全程使用 u64，禁止回绕 |
| S8 | 任意两个段区间不得重叠；允许段间空隙（规范写入端不产生空隙） |
| S9 | 段 1–6 各存在一次 |
| S10 | 段 7 存在当且仅当 `flags.bit0 = 1` |

未知段（id > 7）在 `flags = 0` 时被接受并跳过；解析器不解释其内容。未知段的 `flags` 非 0 时拒绝。

## 4. 段格式

段内所有偏移均相对于段起始。每段末尾的填充必须为 0。

### 4.1 META（id = 1）

META 是 8 字节对齐的 TLV 记录序列；段可为 0 字节。

| 记录内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 2 | `key` | `u16` | 元数据键 |
| 0x02 | 2 | `length` | `u16` | payload 字节数 |
| 0x04 | `length` | `raw` | `u8[]` | payload |

- 记录总长 = `align8(4 + length)`，其中 `align8(n) = (n + 7) & ~7`。
- 记录从段内 8 字节边界开始；payload 紧随 4 字节头，不保证自身 8 字节对齐。
- 整段必须由记录精确覆盖，段大小必须是 8 的倍数，记录尾部填充必须为 0。
- 已知键见下表；同一已知键在段内最多出现一次，重复即拒绝。
- 未知键被接受并保留为原始记录，不参与语义。
- 解析器不校验 payload 的 UTF-8 合法性；文本按字节处理。

| key | 名称 | 取用的 Image 字段 |
|---:|---|---|
| 1 | 模块名 | `moduleName` |
| 2 | 源文件名 | `sourceFile` |
| 3 | build id | `buildId` |
| 4 | 注释 | `comment` |

### 4.2 CONST（id = 2）

| 段内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 4 | `count` | `u32` | 常量条目数，≤ 65536 |
| 0x04 | 4 | `reserved0` | `u32` | 必须为 0 |
| 0x08 | — | `entries` | 变长 | 常量条目 |

CONST 条目：

| 条目内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 1 | `kind` | `u8` | 常量类型，0–4 |
| 0x01 | 1 | `reserved` | `u8` | 必须为 0 |
| 0x02 | 2 | `flags` | `u16` | 必须为 0 |
| 0x04 | 4 | `length` | `u32` | payload 字节数 |
| 0x08 | `length` | `payload` | `u8[]` | 内容 |

- 条目大小 = `8 + align8(length)`；整段必须由条目精确覆盖，不允许额外尾部记录。
- payload 从条目起始 +8 开始；由于每个条目总长是 8 的倍数，payload 在段内 8 字节对齐。
- `count ≤ 65536`；`reserved0`、条目的 `reserved` 与 `flags` 必须为 0。
- 非 String 类型的 `length` 必须恰好为 8。
- String 类型的 `length` 为 0 到 16 MiB；解析器不校验其 UTF-8 合法性。

| kind | 名称 | length | payload 规则 |
|---:|---|---|---|
| 0 | null | 8 | 8 字节必须全为 0 |
| 1 | boolean | 8 | 8 字节小端整数，只能为 0 或 1 |
| 2 | integer | 8 | 8 字节原始数据（约定为 int64 小端二补码，解析器不解释） |
| 3 | real | 8 | 8 字节原始数据（约定为 IEEE-754 binary64 小端，解析器不解释） |
| 4 | string | 0–16 MiB | 原始字节；FUNCS/GLOBALS/IMPORTS 通过索引引用 |

### 4.3 FUNCS（id = 3）

| 段内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 4 | `count` | `u32` | 函数数，≤ 65536 |
| 0x04 | 32 × `count` | `entries` | 定长 | 函数条目 |
| 0x04 + 32 × `count` | 4 | `pad` | `u32` | 必须为 0 |

段大小必须恰好为 `8 + 32 × count`。条目从偏移 4 开始；由于 `4 + 32n ≡ 4 (mod 8)`，段尾固定有 4 字节 0 填充。

Function 条目（32 字节）：

| 条目内偏移 | 大小 | 字段 | 类型 | 含义与校验 |
|---:|---:|---|---|---|
| 0x00 | 4 | `name` | `u32` | 名称的 CONST 索引；`0xFFFFFFFF` = 匿名 |
| 0x04 | 4 | `entry` | `u32` | 函数首条指令在 CODE 中的指令索引 |
| 0x08 | 4 | `instr` | `u32` | 指令条数，必须 ≥ 1 |
| 0x0C | 2 | `regcnt` | `u16` | 寄存器数量，1–256 |
| 0x0E | 1 | `arity` | `u8` | 参数个数，≤ 16 且 ≤ `regcnt` |
| 0x0F | 1 | `flags` | `u8` | bit0 = exported；bit1–7 必须为 0 |
| 0x10 | 2 | `local` | `u16` | 被命名的不同寄存器槽数，≤ `regcnt` |
| 0x12 | 2 | `reserved0` | `u16` | 必须为 0 |
| 0x14 | 4 | `dbgOffset` | `u32` | DEBUG 段内偏移；`0xFFFFFFFF` = 无调试信息 |
| 0x18 | 4 | `reserved1` | `u32` | 必须为 0 |
| 0x1C | 4 | `reserved2` | `u32` | 必须为 0 |

校验规则：

- `name = 0xFFFFFFFF`，或指向一个 kind 为 String 的 CONST 条目。非匿名名称按 **String 内容**在 FUNCS 表内唯一；匿名条目不参与唯一性比较。
- `entry + instr ≤ CODE 指令数`（使用 u64）。
- 任意两个函数的指令区间 `[entry, entry + instr)` 不得重叠。
- `flags` 仅 bit0 可置位；`reserved0/1/2` 必须为 0。
- `dbgOffset` 为 `0xFFFFFFFF`，或 8 字节对齐且指向 DEBUG 段内一个合法的函数调试块。
- 函数最后一条指令必须是终止指令（`JMP`、`RET`、`HALT`、`TRAP`），由验证器 V62 检查。

### 4.4 CODE（id = 4）

| 段内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 4 × N | `instructions` | `u32[]` | N 条 32 位小端指令字 |

- 段大小必须是 4 的倍数且是 8 的倍数，因此指令数 **N 必须为偶数**。
- `NOP = 0x00000000`。当函数指令总数为奇数时，规范写入端在 CODE 末尾补一条 `NOP`；该字不属于任何函数。
- 函数区间必须落在 `[0, N)` 内且互不重叠；函数之间允许存在空隙字。
- 所有 CODE 字都必须通过 V51（合法 opcode、未用字段为 0）；只有函数区间内的字才执行完整指令级检查。空隙字通常写 `NOP`。
- 指令编码与操作数布局见 [01-isa.md](01-isa.md)。

### 4.5 GLOBALS（id = 5）

| 段内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 4 | `count` | `u32` | 全局槽数，≤ 65536 |
| 0x04 | 12 × `count` | `entries` | 定长 | 全局槽 |
| 0x04 + 12 × `count` | 0–4 | `pad` | `u8[]` | 补 0 至 8 字节的倍数 |

段大小必须为 `align8(4 + 12 × count)`，填充必须为 0。

Global 条目（12 字节）：

| 条目内偏移 | 大小 | 字段 | 类型 | 含义与校验 |
|---:|---:|---|---|---|
| 0x00 | 4 | `name` | `u32` | 名称的 CONST 索引；`0xFFFFFFFF` = 匿名 |
| 0x04 | 4 | `init` | `u32` | 初始值 CONST 索引；`0xFFFFFFFF` = null |
| 0x08 | 4 | `flags` | `u32` | bit0 = const；其余位必须为 0 |

- 非匿名名称必须指向 String 常量，并按内容在 GLOBALS 表内唯一。
- `init` 为 `0xFFFFFFFF` 或小于 CONST 条目数（类型不限）。
- 当前指令集没有读取或写入全局槽的指令；GLOBALS 段仍会被完整解析和校验，但当前解释器不会通过这些槽执行读写。

### 4.6 IMPORTS（id = 6）

| 段内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 4 | `count` | `u32` | 导入数，≤ 65536 |
| 0x04 | 8 × `count` | `entries` | 定长 | 导入条目 |
| 0x04 + 8 × `count` | 4 | `pad` | `u32` | 必须为 0 |

段大小必须恰好为 `8 + 8 × count`。

Import 条目（8 字节）：

| 条目内偏移 | 大小 | 字段 | 类型 | 含义与校验 |
|---:|---:|---|---|---|
| 0x00 | 4 | `name` | `u32` | 名称的 CONST String 索引；禁止匿名 |
| 0x04 | 1 | `arity` | `u8` | 参数个数，≤ 16 |
| 0x05 | 1 | `flags` | `u8` | 必须为 0 |
| 0x06 | 2 | `reserved` | `u16` | 必须为 0 |

- `name` 必须指向 String 常量，不允许 `0xFFFFFFFF`；名称按内容在 IMPORTS 表内唯一。
- 宿主在加载时按 `(名称字节, arity)` 精确匹配并绑定导入函数；绑定失败则加载失败，不执行任何字节码。文件格式本身不存储函数指针。
- `HOSTCALL` 的 16 位索引选择 IMPORTS 条目；验证器检查被调导入的 `arity ≤ 调用者 regcnt`。

### 4.7 DEBUG（id = 7）

DEBUG 段可选，存在性与头部 `flags.bit0` 双向一致。非空段以 8 字节头开始。

| 段内偏移 | 大小 | 字段 | 类型 | 含义 |
|---:|---:|---|---|---|
| 0x00 | 1 | `version` | `u8` | 调试格式版本，必须为 1 |
| 0x01 | 1 | `reserved0` | `u8` | 必须为 0 |
| 0x02 | 2 | `reserved1` | `u16` | 必须为 0 |
| 0x04 | 4 | `flags` | `u32` | 必须为 0 |
| 0x08 | — | `blocks` | 变长 | 函数调试块 |

函数调试块由 FUNCS 的 `dbgOffset` 寻址；`dbgOffset` 是相对于 DEBUG 段起始的 8 字节对齐偏移。无调试信息的函数写 `0xFFFFFFFF`。

| 块内偏移 | 大小 | 字段 | 类型 | 含义与校验 |
|---:|---:|---|---|---|
| 0x00 | 4 | `function` | `u32` | 必须等于引用它的 FUNCS 索引 |
| 0x04 | 4 | `lines` | `u32` | 行号项数，≤ 函数的 `instr` |
| 0x08 | 4 | `locals` | `u32` | 局部变量记录数，≤ 65536 |
| 0x0C | 4 | `reserved0` | `u32` | 必须为 0 |
| 0x10 | 12 × `lines` | `lineEntries` | 定长 | 行号表 |
| 0x10 + 12 × `lines` | 16 × `locals` | `localEntries` | 定长 | 局部变量表 |
| 块尾 | 0–7 | `pad` | `u8[]` | 补 0 至 8 字节的倍数 |

一个块占用 `align8(16 + 12 × lines + 16 × locals)` 字节，并且必须完整落在段内。被引用的块之间不得重叠；未被引用的区域不参与解析。

LineEntry（12 字节）：

| 项内偏移 | 大小 | 字段 | 类型 | 含义与校验 |
|---:|---:|---|---|---|
| 0x00 | 4 | `pc` | `u32` | 函数内指令索引；必须严格递增；有行号项时首项必须为 0 |
| 0x04 | 4 | `line` | `u32` | 源码行号，1–0x7FFFFFFF |
| 0x08 | 4 | `column` | `u32` | 源码列号；0 表示未知 |

每个行号项的 `pc` 必须小于函数的 `instr`。列号不限制取值。

LocalEntry（16 字节）：

| 项内偏移 | 大小 | 字段 | 类型 | 含义与校验 |
|---:|---:|---|---|---|
| 0x00 | 4 | `name` | `u32` | 变量名的 CONST String 索引 |
| 0x04 | 2 | `slot` | `u16` | 寄存器槽，必须 < `regcnt` |
| 0x06 | 1 | `flags` | `u8` | bit0 = parameter；其余位必须为 0 |
| 0x07 | 1 | `reserved` | `u8` | 必须为 0 |
| 0x08 | 4 | `startPc` | `u32` | 作用域起始指令索引（含） |
| 0x0C | 4 | `endPc` | `u32` | 作用域结束指令索引（不含） |

- `name` 必须是 String 常量（不允许匿名）。
- `startPc ≤ endPc ≤ 函数的 instr`。
- `flags.bit0 = 1` 时，`slot` 还必须小于函数的 `arity`。
- 同一函数块内不同 `slot` 的数量必须等于 FUNCS 条目的 `local` 字段。

### 4.8 段大小公式汇总

| 段 | 段头 | 条目 | 段大小 | 空段大小 |
|---|---|---|---:|---:|
| META | 无 | 变长 TLV | Σ `align8(4 + length)` | 0 |
| CONST | 8（count + reserved0） | 8 + `align8(length)` | 8 + Σ(`8 + align8(length)`) | 8 |
| FUNCS | 4（count） | 32 | `8 + 32 × count` | 8 |
| CODE | 无 | 4 | `4 × N`，N 为偶数 | 0 |
| GLOBALS | 4（count） | 12 | `align8(4 + 12 × count)` | 8 |
| IMPORTS | 4（count） | 8 | `8 + 8 × count` | 8 |
| DEBUG | 8 | 块头 16、行号项 12、局部项 16 | `8 + Σ align8(16 + 12 × L + 16 × V)` | 8 |

## 5. CRC-32C

| 参数 | 值 |
|---|---|
| 多项式（正常形式） | `0x1EDC6F41`（Castagnoli） |
| 反射形式 | `0x82F63B78` |
| 初始值 | `0xFFFFFFFF` |
| 结果异或 | `0xFFFFFFFF` |
| 输入/输出反射 | 是 |
| 覆盖范围 | 整个文件 `[0, fileSize)` |
| 特殊处理 | 计算时把 `checksum` 字段（偏移 0x18–0x1B）视为 `00 00 00 00` |

- 校验步骤：先确认 `fileSize` 等于实际输入长度；将偏移 0x18–0x1B 的 4 字节视为 0；对完整文件计算 CRC-32C；结果必须等于头部存储值（小端 u32）。
- 实现可能使用 SSE4.2、ARM CRC 扩展或可移植查表路径。对格式而言唯一可观察的要求是：同一字节序列在所有路径上产生相同的 CRC-32C 值。
- CRC-32C 仅用于检测损坏，不是密码学认证。
- 测试向量：

| 输入 | CRC-32C |
|---|---|
| 空输入 | `0x00000000` |
| ASCII `"123456789"` | `0xE3069283` |
| 本文 §10 的 272 字节最小模块（checksum 字段置 0） | `0x1B5A747A` |

## 6. 规范写入规则

规范写入端（当前由 `moteasm` 实现）应产生唯一、可复现的字节序列：

| 编号 | 规则 |
|---|---|
| W1 | `majorVer = 1`、`minorVer = 0`；`flags` 仅按需置 bit0；`reserved0/1 = 0` |
| W2 | 按 id 升序写段表，段数据也按 id 升序紧邻排列；第一段偏移为 `32 + 24 × seccnt`，之后无空隙 |
| W3 | 每个段大小满足 §4.8 的公式；所有填充字节写 0 |
| W4 | CODE 指令数必须为偶数；不足时在末尾补一条 `NOP`，该字不属于任何函数 |
| W5 | META 记录按 key 升序；CONST 按源顺序；FUNCS 按函数定义顺序；GLOBALS 按声明顺序；IMPORTS 按首次出现顺序 |
| W6 | FUNCS/GLOBALS 的匿名名称写 `0xFFFFFFFF`；非匿名名称按 String 内容唯一；IMPORTS 名称必须是 String 且禁止匿名 |
| W7 | 无调试信息时不写 DEBUG 段并清除 `flags.bit0`；有调试信息时置位 bit0、写 DEBUG 段，未使用的调试区域写 0 |
| W8 | `entry` 指向入口函数在 FUNCS 中的索引，入口函数 `arity = 0` |
| W9 | 所有保留字段、保留位、条目 flags 按 §4 的要求写 0 |
| W10 | 最后计算 CRC-32C 并回填 `checksum`；写入端不得在文件中写入时间戳、随机数或宿主绝对路径 |
| W11 | 相同逻辑模块由同一写入端重复生成时，输出字节必须完全一致 |

## 7. 加载、解析与验证流程

入口是 `Parse`：

```text
Parse::load(path or span)
        ↓
Parse::parse()
        ↓
check()          header, section table, CRC
        ↓
readSections()   META → CONST → CODE → FUNCS → GLOBALS → IMPORTS → DEBUG → cross-table
        ↓
Verifier::verify()  CODE decoding + per-function instruction rules
        ↓
success: parsed = true, Image readable; failure: Image cleared
```

| 阶段 | 主要检查 | 失败码 |
|---:|---|---|
| `load(path)` | 文件可打开；stat 大小 ≤ 64 MiB；完整读入 | `FAIL_OPEN` / `TOO_LARGE` / `TRUNC` |
| `load(span)` | 复制输入字节；大小限制推迟到 `parse()` | — |
| `parse()` 入口 | 非空；长度 ≥ 32；长度 ≤ 64 MiB | `EMPTY` / `TRUNC` / `TOO_LARGE` |
| `check()` | magic、版本、flags、保留字段、`fileSize`、段表边界、CRC | `BAD_FILE` |
| `readSections()` | 各段结构、条目边界、对齐、填充、名称/索引引用、DEBUG | `BAD_CONTENT` |
| `Verifier::verify()` | CODE 全字解码、函数内寄存器/索引/跳转/终止规则 | `BAD_CODE` |

失败处理是 **fail-closed**：任何阶段失败都会调用 `clearImage()`，`isValid()` 为 `false`，不会保留半成品镜像，也不会执行任何字节码。

PARSE 状态码（`PARSE::errorText()` 返回对应文本）：

| 码 | 名称 | 含义 |
|---:|---|---|
| 0 | `OK` | 成功 |
| 1 | `FAIL_OPEN` | 文件无法打开或读取 |
| 2 | `EMPTY` | 输入为空 |
| 3 | `TRUNC` | 输入过短或读取不完整 |
| 4 | `TOO_LARGE` | 超过 64 MiB |
| 5 | `BAD_FILE` | 头部、段表或校验和无效 |
| 6 | `BAD_CONTENT` | 段内容无效 |
| 7 | `BAD_CODE` | 指令流无效（验证器） |

## 8. 验证器规则（V51–V62、V76/V77）

验证器先对 CODE 中的每个字做解码检查，再对每个函数的指令区间做完整检查。函数区间外的空隙字只做 V51。

| 编号 | 规则（当前实现） |
|---|---|
| V51 | 每个 CODE 字必须可解码：opcode 属于已定义集合，且该指令格式中未使用的操作数字段必须为 0 |
| V52 | 函数区间外的字只做 V51，不做寄存器/跳转等检查 |
| V53 | 指令实际使用的寄存器号必须小于当前函数的 `regcnt` |
| V54 | 常量索引必须小于 CONST 条目数；当前指令集没有引用常量的指令，故此规则当前不适用 |
| V55 | 全局槽索引必须小于 GLOBALS 条目数；当前指令集没有全局访问指令，故此规则当前不适用 |
| V56 | `CALL` 的 FUNCS 索引和 `HOSTCALL` 的 IMPORTS 索引必须分别在对应表范围内 |
| V57 | `TRAP` 的 24 位立即数必须在 `[1, 16]` |
| V58 | `SETG` 目标不得是 const 全局；当前指令集没有 `SETG`，故此规则当前不适用 |
| V59 | `CALL` 的目标函数 `arity` 必须 ≤ 调用者的 `regcnt` |
| V60 | `HOSTCALL` 的导入 `arity` 必须 ≤ 调用者的 `regcnt` |
| V61 | `JMP`/`JZ`/`JNZ` 的字节偏移必须是 4 的倍数，且目标必须落在同一函数的 `[entry, entry + instr)` 内 |
| V62 | 每个函数的最后一条指令必须是终止指令：`JMP`、`RET`、`HALT` 或 `TRAP` |
| V76 | 头部 `entry` 必须小于 FUNCS 条目数 |
| V77 | 头部 `entry` 指向的函数 `arity` 必须为 0 |

补充说明：

- V51 的“未使用字段为 0”由每条指令的格式决定，例如 `RET` 的 b/c 字段、`HALT` 的全部操作数字段必须为 0。完整的 opcode 集合与字段布局见 [01-isa.md](01-isa.md)。
- 函数区间不得重叠，该结构规则在解析 FUNCS 时已经检查（`BAD_CONTENT`）。
- 验证器同时计算 CALL 图上的寄存器拷贝范围，供运行时挂载已验证模块使用；该结果不属于文件格式。

## 9. 版本兼容与拒绝规则

| 输入情况 | 读取器行为 |
|---|---|
| `majorVer != 1` | 拒绝（`BAD_FILE`） |
| `minorVer > 0` | 拒绝（`BAD_FILE`）；当前读取器只支持 1.0 |
| `flags` 的 bit1–31 非 0 | 拒绝（`BAD_FILE`） |
| `reserved0`、`reserved1` 非 0 | 拒绝（`BAD_FILE`） |
| `fileSize` 与实际长度不一致 | 拒绝（`BAD_FILE`） |
| 段 7 存在性与 `flags.bit0` 不一致 | 拒绝（`BAD_FILE`） |
| 未知段 id > 7 且 `flags = 0` | 跳过，不参与语义 |
| 未知段 id > 7 且 `flags != 0` | 拒绝（`BAD_FILE`） |
| 未知 META key | 接受并保留原始记录，不参与语义 |
| 未知 CONST kind（> 4） | 拒绝（`BAD_CONTENT`） |
| 未知 opcode | 拒绝（`BAD_CODE`） |
| DEBUG `version != 1` | 拒绝（`BAD_CONTENT`） |
| 任何结构/语义检查失败 | 拒绝整个模块，不执行任何字节码 |

读取器不对更高 minor 做“尽力解析”：无法确认的版本直接拒绝。

### 10.2 头部（0x00–0x1F）

| 偏移 | 字节 | 字段 | 解释 |
|---:|---|---|---|
| 0x00–0x03 | `4D 4F 54 45` | `magic` | `"MOTE"` |
| 0x04–0x05 | `01 00` | `majorVer` | 1 |
| 0x06–0x07 | `00 00` | `minorVer` | 0 |
| 0x08–0x0B | `00 00 00 00` | `flags` | 0（无 DEBUG） |
| 0x0C–0x0F | `00 00 00 00` | `entry` | 0（FUNCS[0]） |
| 0x10–0x11 | `06 00` | `seccnt` | 6 |
| 0x12–0x13 | `00 00` | `reserved0` | 0 |
| 0x14–0x17 | `10 01 00 00` | `fileSize` | 0x110 = 272 |
| 0x18–0x1B | `7A 74 5A 1B` | `checksum` | 小端 u32 = `0x1B5A747A` |
| 0x1C–0x1F | `00 00 00 00` | `reserved1` | 0 |

### 10.3 段表（0x20–0xAF，6 × 24 字节）

| 项 | 字节范围 | id | flags | offset | size |
|---:|---|---:|---:|---:|---:|
| [0] | 0x20–0x37 | 1 | 0 | 0xB0 | 0x08 |
| [1] | 0x38–0x4F | 2 | 0 | 0xB8 | 0x18 |
| [2] | 0x50–0x67 | 3 | 0 | 0xD0 | 0x28 |
| [3] | 0x68–0x7F | 4 | 0 | 0xF8 | 0x08 |
| [4] | 0x80–0x97 | 5 | 0 | 0x100 | 0x08 |
| [5] | 0x98–0xAF | 6 | 0 | 0x108 | 0x08 |

表尾为 0xB0，等于 `32 + 24 × 6`。段数据紧邻排列，最后一段结束于 0x110，与 `fileSize` 一致。

### 10.4 段内容走查

| 偏移 | 段 | 字节 | 解释 |
|---:|---|---|---|
| 0xB0–0xB7 | META | `01 00 04 00 6D 69 6E 69` | key=1（模块名）、length=4、`"mini"` |
| 0xB8–0xBF | CONST 头 | `01 00 00 00 00 00 00 00` | count=1、reserved0=0 |
| 0xC0–0xCF | CONST[0] | `04 00 00 00 04 00 00 00 6D 61 69 6E 00 00 00 00` | kind=4（String）、length=4、`"main"`、4 字节填充 |
| 0xD0–0xD3 | FUNCS 头 | `01 00 00 00` | count=1 |
| 0xD4–0xDF | FUNCS[0] 前半 | `00 00 00 00 00 00 00 00 01 00 00 00` | name=0、entry=0、instr=1 |
| 0xE0–0xEF | FUNCS[0] 后半 | `01 00 00 00 00 00 00 00 FF FF FF FF 00 00 00 00` | regcnt=1、arity=0、flags=0、local=0、dbgOffset=NO_INDEX、reserved1=0 |
| 0xF0–0xF7 | FUNCS 尾部 | `00 00 00 00 00 00 00 00` | reserved2=0、尾部 4 字节填充 |
| 0xF8–0xFF | CODE | `54 00 00 00 00 00 00 00` | `RET r0`（0x54，a=0）；1 条 `NOP` 使 N=2 |
| 0x100–0x107 | GLOBALS | `00 00 00 00 00 00 00 00` | count=0 + 4 字节填充 |
| 0x108–0x10F | IMPORTS | `00 00 00 00 00 00 00 00` | count=0 + 4 字节填充 |

校验和：把 0x18–0x1B 置零后对整个 272 字节计算 CRC-32C，结果为 `0x1B5A747A`，小端写回即 `7A 74 5A 1B`。

该模块可依次通过头部、段表、CRC、各段结构和验证器检查：入口 FUNCS[0] 存在且 `arity = 0`；函数区间 `[0, 1)` 在 CODE 内；`RET` 是终止指令；所有 CODE 字均可解码。
